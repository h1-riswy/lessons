# 第3章：学習の仕組み - モデルはどうやって賢くなるのか

第2章では、重み `W` とバイアス `b` が与えられている前提で、ネットワークが入力から出力を計算する手順（順伝播）を見ました。しかし実際には、この `W` と `b` は**最初はランダムな値**です。ランダムな重みのネットワークは、当然でたらめな予測しかしません。

本章のテーマは、**そのでたらめな重みを、データを見ながら少しずつマシな値に更新していく仕組み**です。深層学習の心臓部にあたる部分で、全9章の中でも最も密度の高い回になります。

学習のサイクルは、次の4ステップの繰り返しです。

```
  ┌─────────────────────────────────────────────────┐
  │                                                 │
  │  ① 順伝播      入力 → 予測を出す（第2章）         │
  │       ↓                                         │
  │  ② 損失計算    予測と正解のズレを数値化（3.1）     │
  │       ↓                                         │
  │  ③ 逆伝播      各パラメータの勾配を求める（3.3）   │
  │       ↓                                         │
  │  ④ 更新        勾配の逆向きにパラメータを動かす     │
  │                （3.2 / 3.4）                     │
  │       └──────────── 繰り返し ───────────────┘   │
  └─────────────────────────────────────────────────┘
```

## 3.1 損失関数

### 「正解からのズレ」を数値化する

モデルを改善するには、まず**「今どれくらい間違っているか」を1つの数値で測れる**必要があります。この数値を計算する関数が**損失関数（loss function）**です。誤差関数、コスト関数とも呼ばれます。

```
損失関数 L(予測値, 正解値) → 小さいほど良い（0が理想）
```

学習とは、この **L を最小化するようなパラメータを探す最適化問題**として定式化されます。ここが重要な視点の転換です。「モデルを賢くする」という曖昧な目標が、「関数の最小値を探す」という数学の問題に置き換わります。

> **なぜ「正解率」を直接最適化しないのか**
> 正解率は、予測がわずかに変化しても値が動かない（階段状の）指標です。「どちらに動かせば改善するか」の手がかりが得られません。損失関数には**なめらかに変化し、微分できる**ことが求められます。正解率のような指標は評価に使い、最適化には使いません（評価指標の話は第4章）。

損失関数はタスクによって使い分けます。

### 回帰の損失：平均二乗誤差（MSE）

連続値を予測する回帰では、**平均二乗誤差（Mean Squared Error）**が基本です。

```
MSE = (1/n) * Σ (y_pred - y_true)²
```

```python
import numpy as np

y_true = np.array([3.0, 5.0, 2.5, 7.0])   # 実際の値
y_pred = np.array([2.8, 5.4, 3.0, 6.2])   # モデルの予測

mse = np.mean((y_pred - y_true) ** 2)
print(round(mse, 4))       # 0.2725
```

二乗する理由は2つあります。

1. 符号を打ち消す（+2 のズレと -2 のズレを同じ大きさとして扱う）
2. **大きなズレをより重く罰する**（ズレが2倍になると損失は4倍）

この2つ目は、裏返すと外れ値に弱いという性質でもあります。外れ値が多いデータでは、絶対値を使う MAE や、両者を折衷した Huber損失 が選ばれることもあります。

### 分類の損失：交差エントロピー

分類タスクでは**交差エントロピー誤差（Cross-Entropy Loss）**を使います。モデルが出した確率分布と、正解の分布がどれだけズレているかを測ります。

正解クラスの予測確率を `p` とすると、そのサンプルの損失は次の形になります。

```
L = -log(p)
```

直感的な意味は、**「正解に何%の確率を割り当てたか」への通信簿**です。

| 正解クラスへの予測確率 p | 損失 -log(p) | 評価 |
|---|---|---|
| 0.99 | 0.01 | ほぼ満点 |
| 0.7 | 0.36 | まずまず |
| 0.5 | 0.69 | 当てずっぽう |
| 0.1 | 2.30 | 大きく外した |
| 0.01 | 4.61 | **強い確信で間違えた → 重いペナルティ** |

自信満々に外すと損失が急激に大きくなる点が、MSE との性格の違いです。

```python
import numpy as np

def cross_entropy(probs, label_idx):
    return -np.log(probs[label_idx] + 1e-9)   # 1e-9 はlog(0)回避

# 3クラス分類。正解はクラス0
probs_good = np.array([0.7, 0.2, 0.1])
probs_bad  = np.array([0.1, 0.2, 0.7])

print(round(cross_entropy(probs_good, 0), 3))   # 0.357
print(round(cross_entropy(probs_bad,  0), 3))   # 2.303
```

### PyTorch での損失関数の対応表

実務で使うのは、ほぼ次の3つです。

| タスク | PyTorch のクラス | モデル出力層 |
|--------|-----------------|------------|
| 回帰 | `nn.MSELoss()` | 活性化関数なし |
| 2値分類 | `nn.BCEWithLogitsLoss()` | 活性化関数なし（Sigmoid込み） |
| 多クラス分類 | `nn.CrossEntropyLoss()` | 活性化関数なし（Softmax込み） |

```python
import torch
import torch.nn as nn

criterion = nn.CrossEntropyLoss()

logits = torch.tensor([[2.0, 1.0, 0.1],     # サンプル1（正解: クラス0）
                       [0.5, 0.2, 3.0]])    # サンプル2（正解: クラス2）
labels = torch.tensor([0, 2])

loss = criterion(logits, labels)
print(loss.item())      # 0.2753  ← バッチ内の平均損失
```

> **第2章の注意の再掲**
> `CrossEntropyLoss` と `BCEWithLogitsLoss` は **Softmax / Sigmoid を内部で適用します**。モデルの出力層にも書いてしまう二重適用は、入門者が最も踏みやすい地雷です。**PyTorch のモデルはロジットを返す**、と覚えてください。

## 3.2 勾配降下法

### 損失を小さくする方向へパラメータを動かす

損失を計算できるようになりました。では、どうやって小さくするのでしょうか。

パラメータが1つだけの場合を考えます。損失 `L` をパラメータ `w` の関数としてグラフに描くと、こんな谷の形になります。

```
  L (損失)
   │＼                                    ／
   │  ＼        ● 現在地（w = 2.0）      ／
   │    ＼      │                     ／
   │      ＼    ↓ 傾き（勾配）は正      ／
   │        ＼  → 「左に動かせ」      ／
   │          ＼＿＿＿＿＿＿＿＿＿＿＿／
   │                  ↑
   └──────────────  最小値  ──────────────→ w
```

ある地点での**勾配（gradient）＝ 損失関数をパラメータで微分した値**は、「その方向に w を増やすと L がどれだけ増えるか」を表します。

したがって、**勾配と逆向きに動けば損失は減る**。これが**勾配降下法（Gradient Descent）**です。更新式はこれだけです。

```
w ← w - η * (∂L/∂w)
       ↑      ↑
   学習率   勾配
```

比喩で言えば、**濃い霧の中で山を下る**作業です。全体の地形は見えませんが、足元の傾きは分かる。傾きが下る方向へ一歩進む。それを繰り返す。

NumPy で最小限の勾配降下を書いてみます。`L(w) = (w - 3)²` という単純な関数を最小化します（答えは当然 `w = 3`）。

```python
def loss(w):
    return (w - 3) ** 2

def grad(w):            # 損失の微分： 2(w - 3)
    return 2 * (w - 3)

w = 0.0                 # 初期値（ランダムな重みのつもり）
lr = 0.1                # 学習率

for step in range(1, 21):
    g = grad(w)
    w = w - lr * g      # ← これが勾配降下法の全て
    if step % 5 == 0:
        print(f"step {step:2d}: w = {w:.4f}, loss = {loss(w):.6f}")

# step  5: w = 2.0170, loss = 0.966368
# step 10: w = 2.6779, loss = 0.103763
# step 15: w = 2.8944, loss = 0.011141
# step 20: w = 2.9654, loss = 0.001196
```

深層学習でやっていることも、原理的にはこれと同じです。違いは、パラメータが1個ではなく**数百万〜数千億個**あること、そして損失の谷が高次元で複雑な形をしていることだけです。

### 学習率とその影響

**学習率（learning rate, η）**は、一歩の歩幅です。深層学習で最も影響の大きいハイパーパラメータと言われます。

```
【学習率が小さすぎる】     【ちょうどよい】        【大きすぎる】
    ＼                      ＼                     ＼      ／
      ＼●●●●              ＼ ●                   ●   ／
        ＼＿＿＿              ＼＿●＿                ＼ ● ／
                                                    ＿＿＿＿
  なかなか収束しない        順調に谷底へ         発散する／振動する
  （時間がかかる）                              （損失が nan になる）
```

| 学習率 | 症状 |
|--------|------|
| 小さすぎる（例: 1e-6） | 損失がほとんど下がらない。学習が終わらない |
| 適切（例: 1e-3） | 損失が滑らかに減少する |
| 大きすぎる（例: 1.0） | 損失が跳ね回る、または `nan` になる |

**実務での出発点は `1e-3`（Adam の既定値）**です。学習が不安定なら 1 桁下げ、遅すぎるなら 1 桁上げる、という進め方をします。

上のコードで `lr = 0.1` を `lr = 1.1` に変えて実行してみてください。損失が発散する様子が確認できます。

### バッチ / ミニバッチ / 確率的勾配降下法

1回の更新に何件のデータを使うかで、3つの流儀があります。

| 手法 | 1回の更新に使うデータ | 特徴 |
|------|--------------------|------|
| **バッチ勾配降下法** | 全データ | 更新方向が正確だが、1歩が非常に重い。大規模データではメモリに乗らない |
| **確率的勾配降下法（SGD）** | 1件 | 更新が軽く高速。ただし方向がブレる |
| **ミニバッチ勾配降下法** | 32〜256件程度 | **実務の標準**。速度と安定性のバランスが良く、GPU の並列性も活かせる |

```
【バッチ】          【SGD】             【ミニバッチ】
  ＼                ＼                  ＼
   ●                 ●～～               ●～
    ●                  ～●～               ●～
     ●                ～～●                 ●
  滑らかだが遅い     ブレるが速い        バランスが良い
```

現在「SGD」と呼ばれるものは、実質的にミニバッチ勾配降下法を指していることがほとんどです。PyTorch の `optim.SGD` もそうです。

なお、更新方向のブレは必ずしも悪ではありません。**ブレがあることで、浅い谷（局所解）から抜け出せる**というメリットもあります。

## 3.3 誤差逆伝播法（バックプロパゲーション）

### 連鎖律による勾配の計算

勾配降下法を実行するには、**すべてのパラメータについて勾配 `∂L/∂w` を求める**必要があります。パラメータが数百万個あるとき、これをどう効率的に計算するか。答えが**誤差逆伝播法（backpropagation、通称バックプロップ）**です。

原理は高校数学で習う**合成関数の微分（連鎖律）**そのものです。

```
  y = f(u),  u = g(x)  のとき

     dy/dx = (dy/du) × (du/dx)
```

ニューラルネットワークは「関数の入れ子」なので、出力側から入力側へ向かって、微分を掛け算しながら遡っていけば、すべての層の勾配が求まります。

```
  【順伝播 forward】 →→→→→→→→→→→→→→→→→→→→→→→→→

   x ──[層1: W1]── a1 ──[層2: W2]── a2 ──[損失]── L

  ←←←←←←←←←←←←←←←←←←←←←←←←← 【逆伝播 backward】

   ∂L/∂W1  ←──  ∂L/∂a1  ←──  ∂L/∂W2  ←──  ∂L/∂a2
```

ポイントは、**逆伝播の1回の走査で、全パラメータの勾配がまとめて求まる**ことです。もし各パラメータを1つずつ数値微分（少し動かして損失の変化を見る）で求めようとすると、パラメータ数だけ順伝播が必要になり、現実的な時間では終わりません。誤差逆伝播法は深層学習を実用化した決定的なアルゴリズムです。

### 計算グラフと自動微分

現代のフレームワークでは、逆伝播を自分で実装することはありません。**計算グラフ（computational graph）**を裏で構築し、**自動微分（autograd）**で勾配を計算してくれます。

計算グラフとは、演算のつながりを記録した DAG（有向非巡回グラフ）です。

```
   x ──┐
       ├─[ × ]── u ──┐
   w ──┘             ├─[ + ]── z ──[ ReLU ]── a ──[ 損失 ]── L
                 b ──┘

   順伝播で値を流しながら、この構造を記録しておく
   → 逆向きに辿れば、各ノードの勾配が機械的に求まる
```

PyTorch で実際に確かめてみましょう。

```python
import torch

# requires_grad=True を付けると、この変数に関する計算が記録される
w = torch.tensor(2.0, requires_grad=True)
b = torch.tensor(1.0, requires_grad=True)
x = torch.tensor(3.0)

z = w * x + b            # 順伝播（計算グラフが構築される）
loss = (z - 10.0) ** 2   # 正解 10.0 との二乗誤差

loss.backward()          # ← 逆伝播。全パラメータの勾配を計算

print(loss.item())       # 9.0   （z=7 なので (7-10)^2 = 9）
print(w.grad)            # -18.0  = 2*(z-10)*x = 2*(-3)*3
print(b.grad)            # -6.0   = 2*(z-10)*1
```

`loss.backward()` の1行で `w.grad` と `b.grad` が埋まります。これが自動微分です。

### 学習ループの全体像

ここまでの要素を組み合わせると、PyTorch の学習ループが書けます。**この5行のパターンは、深層学習のコードすべてに共通する型**です。

```python
import torch
import torch.nn as nn

# XOR を学習させてみる
X = torch.tensor([[0.,0.], [0.,1.], [1.,0.], [1.,1.]])
y = torch.tensor([[0.], [1.], [1.], [0.]])

model = nn.Sequential(
    nn.Linear(2, 8), nn.ReLU(),
    nn.Linear(8, 1),
)
criterion = nn.BCEWithLogitsLoss()
optimizer = torch.optim.Adam(model.parameters(), lr=0.05)

for epoch in range(1, 501):
    optimizer.zero_grad()        # ① 前回の勾配をリセット
    pred = model(X)              # ② 順伝播
    loss = criterion(pred, y)    # ③ 損失を計算
    loss.backward()              # ④ 逆伝播（勾配を計算）
    optimizer.step()             # ⑤ パラメータを更新

    if epoch % 100 == 0:
        print(f"epoch {epoch}: loss = {loss.item():.4f}")

print(torch.sigmoid(model(X)).round().ravel())   # tensor([0., 1., 1., 0.])
```

第2章で「単層では解けない」と述べた XOR が、隠れ層を持つネットワークで解けていることを確認してください。

> **`optimizer.zero_grad()` を忘れるとどうなるか**
> PyTorch は勾配を**累積**する設計になっています。リセットを忘れると前回の勾配が足され続け、学習が崩壊します。入門者が最も頻繁に踏むバグです。

### エポック・イテレーション・バッチサイズ

学習の進行を表す用語を整理します。混同しやすいので、表で押さえてください。

| 用語 | 意味 |
|------|------|
| **バッチサイズ** | 1回の更新に使うサンプル数（例: 32） |
| **イテレーション** | パラメータ更新の回数。1回の更新＝1イテレーション |
| **エポック** | 訓練データ全体を1周すること |

```
  訓練データ 1,000 件、バッチサイズ 100 の場合

  1エポック = 10イテレーション（1000 ÷ 100）
  50エポック回すなら = 500イテレーション = 500回のパラメータ更新
```

```python
n_samples, batch_size, epochs = 1000, 100, 50
iters_per_epoch = n_samples // batch_size
print(f"1エポック = {iters_per_epoch} イテレーション")   # 10
print(f"合計更新回数 = {iters_per_epoch * epochs}")      # 500
```

「エポック数をいくつにするか」は重要な問いですが、これは**過学習**の話と切り離せません。第4章で扱います。

## 3.4 最適化アルゴリズム

### 素朴な勾配降下法の弱点

`w ← w - η * grad` という素朴な更新式には、実用上の弱点があります。

- 谷が細長い形だと、壁を行き来してジグザグに進み、収束が遅い
- すべてのパラメータに同じ学習率を使うため、更新頻度の低いパラメータが学習されにくい
- 平坦な領域（プラトー）で停滞する

これらを改善する更新式が**最適化アルゴリズム（optimizer）**です。

### Momentum / AdaGrad / RMSProp / Adam

主要な最適化アルゴリズムは、**2つのアイデアの組み合わせ**として整理すると覚えやすいです。

```
  アイデア①：慣性（Momentum）
    過去の更新方向を引き継ぐ。ボールが坂を転がるように、
    ジグザグを打ち消して加速する

  アイデア②：学習率の自動調整（AdaGrad / RMSProp）
    パラメータごとに学習率を変える。よく更新されるものは
    歩幅を小さく、あまり更新されないものは大きく

  Adam ＝ ① ＋ ②
```

| 手法 | 登場年 | 特徴 |
|------|-------|------|
| **SGD** | — | 素朴な勾配降下。シンプルで、チューニングすれば最終精度が高いこともある |
| **Momentum** | 1964 | 慣性を導入。ジグザグを抑え収束を加速 |
| **AdaGrad** | 2011 | パラメータごとに学習率を調整。ただし学習率が単調減少し、途中で止まりがち |
| **RMSProp** | 2012 | AdaGrad の減衰しすぎを、移動平均で緩和 |
| **Adam** | 2014 | Momentum ＋ RMSProp。**現在のデファクト標準** |
| **AdamW** | 2017 | Adam の正則化（weight decay）の扱いを修正。Transformer 系の標準 |

```python
import torch

params = model.parameters()

opt_sgd      = torch.optim.SGD(params, lr=0.01, momentum=0.9)
opt_rmsprop  = torch.optim.RMSprop(params, lr=0.001)
opt_adam     = torch.optim.Adam(params, lr=0.001)      # ← 迷ったらこれ
opt_adamw    = torch.optim.AdamW(params, lr=0.001)     # Transformer系はこれ
```

インターフェースは共通なので、1行差し替えるだけで切り替えられます。試しやすい部分です。

### 実務でのデフォルト選択

判断に迷ったときの指針です。

1. **まず `Adam(lr=1e-3)` で始める。** 多くのタスクで無難に動きます
2. **Transformer 系なら `AdamW`。** 学習率は 1e-4 〜 5e-5 あたり
3. **画像分類で最後の数%を詰めたいなら `SGD + momentum`。** ただし学習率スケジューリングが必要で、チューニングコストは高い

> **よくある誤解**
> 「最適化アルゴリズムを変えれば精度が上がる」と期待されがちですが、効果は限定的です。**データの質・量、モデル構造、学習率の方がはるかに支配的**です。Adam で動かないモデルが、RMSProp にしたら動くということはまず起きません。まずデータとモデルを疑ってください。

## まとめ

本章では、ニューラルネットワークが学習するメカニズムを追いかけました。

✅ **損失関数が「間違いの大きさ」を1つの数値にする。回帰は MSE、分類は交差エントロピー**
✅ **勾配降下法は「勾配と逆向きに一歩進む」の繰り返し。学習率がその歩幅**
✅ **誤差逆伝播法は連鎖律の応用。1回の逆向き走査で全パラメータの勾配が求まる**
✅ **PyTorch の学習ループは `zero_grad → forward → loss → backward → step` の5行が型**
✅ **最適化アルゴリズムは Adam が実務の標準出発点。Transformer 系なら AdamW**

ここまでで、モデルが学習する仕組みは一通り揃いました。しかし「損失が下がり続けている＝良いモデル」とは限りません。訓練データにだけ都合よく適合してしまう**過学習**という現象があるからです。次章では、モデルの良し悪しをどう判断し、どう改善するか——評価とチューニングの話に進みます。

## 演習問題

1. 3クラス分類で、あるサンプルの正解がクラス1だったとします。次の2つの予測のうち、交差エントロピー損失が大きいのはどちらですか。実際に `-log(p)` を計算して確かめてください。
   - 予測A: `[0.3, 0.4, 0.3]`
   - 予測B: `[0.8, 0.1, 0.1]`

2. 3.2 の勾配降下のコードで、学習率 `lr` を `0.01` / `0.5` / `1.1` に変えて実行し、それぞれ何が起きるか観察してください。`lr = 1.0` にしたときの挙動も予想してから試してみましょう。

3. 訓練データが 12,800 件、バッチサイズ 64、エポック数 30 で学習するとき、パラメータの更新は合計何回行われますか。

4. 次の学習ループには 1 箇所バグがあります。指摘して修正してください。また、そのまま実行すると学習にどんな異常が現れるか説明してください。

```python
for epoch in range(100):
    pred = model(X)
    loss = criterion(pred, y)
    loss.backward()
    optimizer.step()
```
