第6章：RNN・LSTM・GRU — 系列データを扱う

記憶を持ち回りながら 1 語ずつ読む RNN。その記憶がなぜ薄れ、LSTM・GRU のゲートがどう守るのか。情報と勾配の流れをアニメーションで追いかけます。

前章の CNN は「画像のどこにあっても同じ猫は猫」という 位置不変性 を活かすアーキテクチャでした。しかし世の中には、順番そのものに意味があるデータがあります。

インタラクティブ

単語の集合は同じ、意味は正反対

本章では、こうした 系列データ（sequential data） を扱う RNN と、その改良版である LSTM・GRU を見ていきます。現在の主流は第7章で扱う Transformer ですが、その必要性を理解するには、RNN が何に苦しんだのかを知る必要があります。

6.1 系列データと再帰構造

時系列・自然言語の何が特殊なのか

系列データには、これまでのデータと違う 3 つの特徴があります。

特徴説明例
順序に意味がある並び替えると意味が変わる単語の並び、株価の推移
長さが可変入力ごとに要素数が違う3 単語の文も 100 単語の文もある
文脈依存前の要素が後の解釈を左右する「それ」が何を指すかは前文次第

全結合層や CNN は「固定長の入力」を前提としています。文章ごとに長さが違うデータをそのまま入れることはできません。

RNN の基本構造と隠れ状態

RNN（Recurrent Neural Network、再帰型ニューラルネットワーク） は、隠れ状態（hidden state） という「これまでの記憶」を持ち回ることでこれを解決します。出力した記憶を、次の時刻の入力として自分自身に戻す（再帰）のです。1 ステップの計算はシンプルです。

ht = tanh( Wx · xt ＋ Wh · ht−1 ＋ b )　　← 新しい入力 ＋ 前の記憶
yt = Wy · ht ＋ by

ポイントは、W_x, W_h, W_y が 全ステップで共通 であることです。CNN のフィルタ共有と同じ発想で、これにより任意の長さの系列を同じパラメータで処理できます。

時間方向への展開

再帰構造は、時間方向に引き伸ばす（unroll する）と普通のネットワークとして見えます。下のアニメーションで、ループの形をした RNN を展開し、"I love deep learning" を 1 語ずつ読ませてみましょう。

アニメーション

RNN を展開して、1 語ずつ読ませる

展開してしまえば、学習は第3章の誤差逆伝播法と同じです。ただし時間方向にさかのぼって勾配を伝えるため、特に BPTT（Backpropagation Through Time、通時的誤差逆伝播） と呼ばれます。

6.2 RNN の課題

勾配消失・勾配爆発

RNN は理論上いくらでも長い系列を扱えますが、実際には長い系列でうまく学習できません。BPTT では、時刻 t の誤差を時刻 1 まで伝えるのに、同じ重み行列を 何度も掛け算する ことになるからです。1 ステップさかのぼるごとの倍率を変えて、50 ステップ前まで勾配がどう伝わるかを見てみましょう。

インタラクティブ

50 ステップさかのぼると勾配はどうなる？

50 ステップさかのぼると、およそ W を 50 回掛けることになる

W の影響が 0.9 倍相当なら:  0.9^50 ≒ 0.005   → 勾配消失（学習が進まない）
W の影響が 1.1 倍相当なら:  1.1^50 ≒ 117     → 勾配爆発（値が発散する）
  • 勾配消失（vanishing gradient）：遠い過去に向かう勾配がほぼ 0 になり、そこのパラメータが更新されない
  • 勾配爆発（exploding gradient）：勾配が発散し、損失が NaN になる

勾配爆発は、勾配クリッピング（勾配のノルムに上限を設ける）で比較的簡単に対処できます。上の図の「クリッピング」をオンにすると、上限で頭打ちになる様子を確認できます。

torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)

厄介なのは勾配消失のほうです。値が静かに 0 に近づくだけなので、エラーも出ず、ただ「精度が上がらない」という形で現れます。

長期依存関係の学習が難しい理由

勾配消失の実害は、長期依存関係（long-term dependency） が学べないことです。次の文で空欄を埋めるには、50 単語前の「フランス」を覚えておく必要があります。

アニメーション

「フランス」の記憶は 50 単語後まで残るか

素の RNN では勾配がそこまで届かず、直前の数単語しか参照できません。実用上、素の RNN が記憶できるのは せいぜい 10 ステップ程度 と言われます。これでは文章も時系列も扱えません。

6.3 LSTM と GRU

ゲート機構という発想

この問題を解決したのが LSTM（Long Short-Term Memory） です。1997 年に提案され、2010 年代の自然言語処理を支えました。アイデアは 2 つです。

  1. セル状態（cell state） という、情報が素通りできる「ベルトコンベア」を用意する
  2. ゲート で、そこに何を書き込み、何を捨て、何を読み出すかを学習で制御する

セル状態の上では、情報は 掛け算と足し算だけ で次の時刻へ運ばれます。重み行列を何度も掛けて tanh を通す素の RNN と違い、勾配が減衰しにくい経路です。CNN の残差接続（第5章）と同じく「勾配が素通りできる経路を作る」という発想です。

忘却ゲート・入力ゲート・出力ゲート

各ゲートは、Sigmoid 関数（σ）で 0〜1 の値を出す小さなニューラルネットワークです。この値を掛けることで「どれだけ通すか」を調節します。0 に近いと遮断、1 に近いとそのまま通す。この開き具合を、データから学習します。

ゲート役割直感的な意味
忘却ゲート (forget)セル状態の古い情報をどれだけ残すか「主語が変わったので前の主語は忘れる」
入力ゲート (input)新しい情報をどれだけ書き込むか「新しい主語を記憶する」
出力ゲート (output)セル状態のどこを今の出力に使うか「今は主語の単複だけ使いたい」

1 ステップの中で情報がどう流れるかを、具体的な数値（「主語が単数から複数に変わった」場面のイメージ）で追ってみましょう。

アニメーション

LSTM セルの 1 ステップ

ゲートの値を自分で動かすと、セル状態と出力がどう変わるかを確かめられます。

インタラクティブ

ゲートを開け閉めしてみる

PyTorch では 1 行で使えます。入出力の 形状 を押さえるのが実務上の要点です。

import torch
import torch.nn as nn

lstm = nn.LSTM(input_size=64, hidden_size=128, num_layers=2, batch_first=True)

# batch_first=True のとき入力は (バッチ, 系列長, 特徴次元)
x = torch.randn(32, 20, 64)          # 32文, 各20トークン, 各トークン64次元

out, (h_n, c_n) = lstm(x)

print(out.shape)    # torch.Size([32, 20, 128])  全ステップの隠れ状態
print(h_n.shape)    # torch.Size([2, 32, 128])   最終ステップの隠れ状態(層ごと)
print(c_n.shape)    # torch.Size([2, 32, 128])   最終ステップのセル状態
よくある誤解batch_first=False（PyTorch のデフォルト）だと入力は (系列長, バッチ, 特徴次元) になります。形状のバグの大半はここです。明示的に batch_first=True を指定するのが安全です。

用途による使い分け：

  • 文全体を 1 つのベクトルにしたい（感情分析など）→ h_n の最終層を使う
  • 各トークンに出力が要る（品詞タグ付けなど）→ out を使う
# many-to-one: 文の感情を2クラス分類
class SentimentModel(nn.Module):
    def __init__(self, vocab_size, emb=64, hid=128):
        super().__init__()
        self.emb = nn.Embedding(vocab_size, emb)
        self.lstm = nn.LSTM(emb, hid, batch_first=True)
        self.fc = nn.Linear(hid, 2)

    def forward(self, ids):              # ids: (batch, seq_len)
        out, (h_n, _) = self.lstm(self.emb(ids))
        return self.fc(h_n[-1])          # 最終層の最終隠れ状態 -> (batch, 2)

GRU による簡略化

GRU（Gated Recurrent Unit） は 2014 年に提案された、LSTM の簡略版です。セル状態をなくして隠れ状態 h だけにし、ゲートを 2 つに減らしました。

  • リセットゲート（r）：新しい候補を作るとき、過去の情報をどれだけ無視するか
  • 更新ゲート（z）：LSTM の忘却ゲートと入力ゲートを 1 つにまとめたもの。「古い記憶」と「新しい候補」を z : (1 − z) の割合で混ぜる
アニメーション

GRU セルの 1 ステップ

※ 文献によって z と (1 − z) の役割が逆の表記もあります（PyTorch の公式ドキュメントは h_t = (1 − z)·n + z·h_{t−1} で、z が 1 に近いほど古い記憶を残す向き）。どちらも「混ぜる割合をゲートで決める」という仕組みは同じです。

LSTM と GRU の違いをまとめると次のとおりです。パラメータ数は PyTorch の input_size=64, hidden_size=128（1 層）で比べています。

グラフ

RNN・GRU・LSTM のパラメータ数（入力 64・隠れ 128）

LSTMGRU
ゲート3 つ（忘却 / 入力 / 出力）2 つ（リセット / 更新）
状態セル状態 C と隠れ状態 h隠れ状態 h のみ
パラメータ多いLSTM の約 3/4、学習が速い

精度はタスクによりけりで、どちらが優れているとは一概に言えません。データが少ない、あるいは速度を優先したいなら GRU、というのが一般的な使い分けです。

gru = nn.GRU(input_size=64, hidden_size=128, batch_first=True)
out, h_n = gru(x)       # 戻り値が 2 つ（セル状態がない点が LSTM との違い）

双方向 RNN

素の RNN は「過去から未来」の一方向にしか進みません。しかし文章の理解では、後ろの文脈も役に立ちます。英語の bank は「銀行」とも「土手」とも読めますが、どちらなのかは後ろまで読まないと確定しません。

双方向 RNN（Bidirectional RNN） は、順方向と逆方向の 2 つの RNN を走らせ、各時刻の隠れ状態を連結します。

アニメーション

前から読む RNN ＋ 後ろから読む RNN

bilstm = nn.LSTM(64, 128, batch_first=True, bidirectional=True)
out, (h_n, c_n) = bilstm(torch.randn(32, 20, 64))
print(out.shape)    # torch.Size([32, 20, 256])  ← 128 * 2（順+逆）
制約双方向にするには系列全体が事前に揃っている必要があります。リアルタイム音声認識のように、未来の入力がまだ存在しないタスクには使えません（上の図の「リアルタイム」で確認できます）。

6.4 応用と限界

Seq2Seq と Encoder-Decoder

機械翻訳では、入力と出力の長さが一致しません（日本語 8 単語 → 英語 12 単語）。これを扱うのが Seq2Seq（Sequence-to-Sequence）、別名 Encoder-Decoder 構造です。Encoder が入力文全体を 1 本の固定長ベクトル（文脈ベクトル）に圧縮し、Decoder がそこから出力を 1 語ずつ生成します。

アニメーション

「私は猫が好き」→ "I like cats"

# 概念コード（Encoder の最終状態を Decoder の初期状態として渡す）
_, (h, c) = encoder_lstm(src_emb)          # 入力文を読み切る
out, _ = decoder_lstm(tgt_emb, (h, c))     # その記憶から出力を生成
logits = fc(out)                            # 各ステップで語彙上の確率分布

主な応用先：

分野タスク
自然言語処理機械翻訳、要約、対話応答、固有表現抽出
音声音声認識、音声合成
時系列需要予測、株価予測、異常検知、センサーデータ解析

RNN 系の 2 つの壁

RNN 系アーキテクチャは大きな成果を上げましたが、2 つの構造的な限界を抱えていました。

壁1：固定長ボトルネック — Seq2Seq では、入力文がどれだけ長くても、1 本の固定長ベクトルに押し込められます。

インタラクティブ

入力文を長くすると、1 単語あたりの「容量」は？

実際、入力文が長くなるほど翻訳精度が落ちることが知られていました。

壁2：逐次処理ゆえの並列化の壁 — こちらがより深刻です。RNN は h_t を計算するのに h_(t−1) が必要なため、原理的に時間方向の並列計算ができません。

アニメーション

GPU のコアが何千あっても、RNN は 1 つずつ

GPU の性能は「大量の計算を同時に行う」ことで発揮されます。RNN はその強みを活かせないため、モデルを大きくしても、データを増やしても、学習時間が線形に伸びてしまいます。

実務での位置づけこの「並列化できない」という制約こそが、2017 年の Transformer 登場の直接的な動機でした。Transformer は再帰構造を捨て、系列の全要素を一度に処理することで、GPU をフルに使った大規模学習を可能にしました。現在の LLM が存在するのはこのためです。その仕組みは第7章で扱います。

なお RNN 系が完全に不要になったわけではありません。小規模な時系列予測や、計算資源が限られる組込み環境では、軽量な LSTM / GRU が今も現役です。

まとめ

本章では、系列データを扱う RNN 系のアーキテクチャを学びました：

  • RNN は隠れ状態を持ち回ることで、可変長の系列と文脈を扱える
  • 同じ重みを繰り返し掛けるため、勾配消失・勾配爆発が起き、長期依存が学べない
  • LSTM はセル状態とゲート機構で情報の取捨選択を学習し、長期記憶を実現した
  • GRU は LSTM の簡略版。双方向 RNN は前後の文脈を同時に使う
  • Seq2Seq の固定長ボトルネックと、逐次処理による並列化の壁が RNN の限界

次章では、この限界を突破し、現代の生成 AI の基盤となった Attention と Transformer を扱います。

演習問題

1. nn.LSTM(input_size=100, hidden_size=256, num_layers=2, batch_first=True) に形状 (16, 30, 100) のテンソルを入力しました。out, h_n, c_n それぞれの形状を答えてください。

解答例を見る

out: (16, 30, 256)（最終層の全ステップの隠れ状態）
h_n: (2, 16, 256)（層数, バッチ, 隠れ次元）
c_n: (2, 16, 256)。h_n と c_n は batch_first=True でも先頭が層数になる点に注意。

2. 素の RNN で長期依存関係が学習できない理由を、BPTT における勾配の伝わり方に触れて説明してください。また、LSTM がそれをどう解決したかも述べてください。

解答例を見る

BPTT では誤差を過去へ伝えるたびに同じ重み行列（と tanh の微分）が掛け算されるため、影響が 1 より小さければ指数的に 0 へ（勾配消失）、大きければ発散する（勾配爆発）。その結果、遠い過去の入力に関わるパラメータがほとんど更新されず、長期依存が学べない。LSTM はセル状態という「掛け算（忘却ゲート）と足し算だけで次へ運ばれる経路」を設け、忘却ゲートが 1 に近ければ情報と勾配がほぼ減衰せずに遠くまで届くようにした。何を残し何を書き込むかはゲートが学習する。

3. 次の 3 つのタスクについて、双方向 RNN が使えるかどうかを理由とともに判定してください。

  • (a) レビュー文全体の評価が星いくつかを予測する
  • (b) 通話中の音声をリアルタイムで文字起こしする
  • (c) 文章中の各単語に品詞タグを付ける
解答例を見る

(a) 使える：レビュー文は全体が事前に揃っている。
(b) 使えない：リアルタイム処理では未来の音声がまだ存在せず、逆方向の RNN を走らせられない（全体が届くまで待つと遅延が大きくなる）。
(c) 使える：文全体が揃っており、各単語の品詞の判定には後ろの文脈も役立つ。

4. 「RNN は GPU の性能を活かしきれない」と言われます。その理由を、CNN との違いに触れて説明してください。

解答例を見る

RNN は ht の計算に ht−1 が必要なため、時間方向に 1 ステップずつ順番に計算するしかなく、系列長に比例した回数だけ待たされる。CNN の畳み込みは各位置の計算が互いに独立しているので、全位置を同時に計算できる。GPU は大量の独立な計算を同時に行うことで性能を発揮するため、逐次依存のある RNN ではコアの大部分が遊んでしまう。
