# 第7章：Attention と Transformer - 現代 AI の基盤

前章では RNN / LSTM で系列データを扱いました。しかし RNN には「逐次処理しかできない」「長い文脈が薄れる」という構造的な壁がありました。本章で扱う **Attention** と **Transformer** は、その壁を正面から取り払ったアーキテクチャです。今日の LLM も画像生成モデルも、ほぼすべてこの延長線上にあります。

## 7.1 Attention の登場

### Seq2Seq のボトルネック問題

第 6 章の Seq2Seq（Encoder-Decoder）を思い出してください。Encoder は入力文を読み込み、**最後の隠れ状態 1 本**に情報を詰め込んで Decoder に渡していました。

```
入力: 「今日 の 会議 は 15 時 から 3 号 会議 室 で 行い ます」
        ↓ ↓ ↓ ↓ ↓ ↓ ↓ ↓ ↓ ↓ ↓ ↓
Encoder [h1][h2][h3]...............[h12]
                                     │
                              この 1 本のベクトル（例: 512 次元）だけを渡す
                                     ↓
Decoder 「The meeting today starts at 15:00 in room 3」
```

問題は明らかです。12 単語だろうが 100 単語だろうが、**固定長のベクトル 1 本**に圧縮しなければならない。エンジニア的に言えば、可変長の入力を固定サイズのバッファに詰め込んでいるようなもので、長い入力ほど情報が溢れます。実際、Seq2Seq の翻訳精度は入力が長くなるほど急激に落ちることが知られていました。

### 「どこに注目するか」を学習する

Attention のアイデアはシンプルです。

> 最後の 1 本だけを渡すのをやめて、**全ステップの隠れ状態を全部渡す**。そして Decoder が出力を 1 語作るたびに、「今はどの入力語を見るべきか」の重みを計算する。

人間の翻訳者も「meeting」を書くときは「会議」のあたりを見て、「15:00」を書くときは「15 時」のあたりを見ます。この「見る場所の配分」を学習パラメータとして持たせたのが Attention です。

```
Decoder が "room" を出力するとき：

入力語:  今日  の   会議  は   15時  から  3号  会議室  で
注目度:  0.01 0.01 0.05 0.01 0.02 0.02 0.18 0.65  0.05
                                              ↑ここに強く注目
```

この注目度（**Attention Weight**）は合計が 1 になるように Softmax で正規化されます。重要なのは、この重みが人手のルールではなく**学習によって自動的に決まる**ことです。

### Query / Key / Value

Attention の計算は、**辞書引き（key-value ストア）の柔らかい版**として理解すると腑に落ちます。

| 用語 | 役割 | 辞書でたとえると |
|------|------|------------------|
| **Query（Q）** | 「今、何を探しているか」 | 検索キーワード |
| **Key（K）** | 「私はこういう情報です」という見出し | 辞書のキー |
| **Value（V）** | 実際に取り出される中身 | 辞書の値 |

通常の辞書は `dict[key]` で完全一致した 1 件だけを返します。Attention は違います。

```python
# 通常の辞書（ハード）
value = d["会議室"]           # 完全一致した1件だけ

# Attention（ソフト）
# 全キーとの「類似度」を計算し、その重みで全Valueを混ぜて返す
similarity = [0.01, 0.01, 0.05, ..., 0.65, 0.05]  # 合計 1.0
value = sum(w * v for w, v in zip(similarity, values))
```

つまり Attention は「**全部の値を、関連度に応じた配合比で混ぜて返す微分可能な辞書引き**」です。微分可能だからこそ、誤差逆伝播で「もっとここに注目せよ」と学習できます。

### Scaled Dot-Product Attention

類似度の計算には内積を使います。式にすると次の 1 行です。

```
Attention(Q, K, V) = softmax( Q Kᵀ / √d_k ) V
```

各要素の意味だけ押さえれば十分です（導出は不要）。

| 部分 | 意味 |
|------|------|
| `Q Kᵀ` | Query と全 Key の内積 = 類似度スコア |
| `/ √d_k` | スコアが大きくなりすぎるのを抑える（`d_k` は Key の次元数） |
| `softmax(...)` | スコアを合計 1 の重みに変換 |
| `... V` | 得られた重みで Value を加重平均 |

`√d_k` で割る理由だけ補足すると、次元数が大きいほど内積の値は大きくなりがちで、そのまま Softmax に入れると出力が 0 か 1 に振り切れて勾配がほぼ 0 になってしまいます。スケール調整はその予防策です。

## 7.2 Self-Attention

### 系列内部の関係性を捉える

前節の Attention は「Decoder が Encoder を見る」ものでした。ここで発想を変えます。

> **入力系列が、自分自身を見る**

これが **Self-Attention** です。Q も K も V も、すべて同じ入力から作ります。

![Self-Attention](../ai-introduction/self-attention.svg)

なぜこれが効くのか。次の文を考えてください。

```
「その動物は疲れていたので、道路を渡らなかった」
```

「渡らなかった」の主語は何か？ 人間は「動物」だとわかります。Self-Attention は「渡らなかった」というトークンから見て「動物」というトークンへの注目度を高く学習することで、この係り受けを内部表現に埋め込みます。RNN のように隣から順に情報を伝える必要はなく、**どんなに離れたトークンにも 1 ステップで直接アクセスできる**のが決定的な違いです。

### 行列の形（shape）で追う

具体的な数字で追いましょう。入力が 10 トークン、各トークンの埋め込み次元を 512 とします。

```
X : (10, 512)        入力の埋め込み行列（10トークン × 512次元）
```

ここから学習可能な重み行列 `W_Q, W_K, W_V` （いずれも `(512, 64)` とする）で 3 つを作ります。

```
Q = X @ W_Q  →  (10, 512) @ (512, 64) = (10, 64)
K = X @ W_K  →  (10, 64)
V = X @ W_V  →  (10, 64)
```

そして Attention を計算します。

```
scores  = Q @ K.T        (10, 64) @ (64, 10) = (10, 10)   ← 全トークン対全トークン
scores  = scores / √64
weights = softmax(scores, dim=-1)                (10, 10)  ← 各行の合計が 1
output  = weights @ V    (10, 10) @ (10, 64)   = (10, 64)
```

ここで最重要なのが中間に現れる **(10, 10) の行列**です。これは「i 番目のトークンが j 番目のトークンをどれだけ見るか」の総当たり表そのものです。

```
        今日   の   会議   は  ...
 今日  [0.4  0.1  0.3  0.1  ...]  ← 合計 1.0
  の   [0.2  0.3  0.4  0.1  ...]
 会議  [0.1  0.2  0.5  0.1  ...]
  は   [...]
```

出力の shape は入力と同じ「トークン数 × 次元」です。つまり Self-Attention は**系列の長さを変えず、各トークンの表現を文脈で塗り直す層**だと捉えられます。

> **計算量の注意**：この表は系列長 n に対して n × n です。トークン数を 2 倍にすると計算量とメモリは 4 倍になります。LLM のコンテキストウィンドウが簡単には伸ばせないのは、根本的にはこの二乗オーダーが理由です。

### Multi-Head Attention

1 種類の注目パターンだけでは表現力が足りません。「文法的な係り受け」に注目したい場合もあれば、「意味的に近い語」に注目したい場合もあります。

そこで、**小さい Attention を複数並列に走らせて結合**します。これが Multi-Head Attention です。

```
512 次元の入力
   ├→ Head 1 : Q,K,V を 64 次元で作って Attention → (10, 64)
   ├→ Head 2 : 別の重みで                        → (10, 64)
   ├→ ...
   └→ Head 8 :                                   → (10, 64)
                                   ↓ 連結
                              (10, 512)
                                   ↓ 出力用の重み W_O で線形変換
                              (10, 512)
```

64 × 8 = 512 なので、**全体の計算量は 1 ヘッドの場合とほぼ同じ**まま、多様な観点を同時に獲得できます。CNN で複数のフィルタを並べたのと同じ発想です。

### 位置エンコーディング

Self-Attention には致命的な弱点があります。**トークンの順序を一切見ていない**のです。

```
「犬 が 人 を 噛んだ」
「人 が 犬 を 噛んだ」
```

総当たりの内積計算だけでは、この 2 文は同じ集合として扱われてしまいます（Attention は集合演算であり、順序に対して不変）。

そこで、入力の埋め込みに**位置の情報を足し込みます**。これが **Positional Encoding（位置エンコーディング）** です。

```python
# 概念コード
x = token_embedding(tokens)      # (10, 512)
x = x + positional_encoding(10)  # 位置ごとに固有のベクトルを加算
```

オリジナルの Transformer では sin / cos を使った固定パターンを用いました。位置ごとに異なる波形を埋め込むことで、モデルが相対的な距離を読み取れるようにしています。

| 方式 | 特徴 |
|------|------|
| Sinusoidal（固定） | 学習不要。学習時より長い系列にもある程度対応 |
| Learned（学習型） | 位置ベクトルもパラメータとして学習。BERT などで採用 |
| RoPE など相対位置 | 相対的な位置関係を回転として表現。近年の LLM で主流 |

## 7.3 Transformer アーキテクチャ

### Encoder と Decoder の構成

2017 年の論文 "Attention Is All You Need" は、RNN も CNN も一切使わず、**Attention と全結合層だけ**でモデルを組みました。それが Transformer です。

![Transformer アーキテクチャ](../ai-introduction/transformer-architecture.svg)

全体像は Encoder ブロックと Decoder ブロックの積み重ねです。

```
[Encoder ブロック] × N          [Decoder ブロック] × N
 ┌──────────────────┐            ┌──────────────────────┐
 │ Multi-Head       │            │ Masked Multi-Head    │
 │ Self-Attention   │            │ Self-Attention       │
 │   + 残差 & LN    │            │   + 残差 & LN        │
 ├──────────────────┤            ├──────────────────────┤
 │                  │──────────→ │ Cross-Attention      │
 │                  │  K, V を渡す│  (Q は Decoder 側)   │
 │                  │            │   + 残差 & LN        │
 ├──────────────────┤            ├──────────────────────┤
 │ Feed Forward     │            │ Feed Forward         │
 │   + 残差 & LN    │            │   + 残差 & LN        │
 └──────────────────┘            └──────────────────────┘
```

押さえるべき Attention は 3 種類です。

| 種類 | 場所 | Q / K / V の出どころ | 役割 |
|------|------|----------------------|------|
| Self-Attention | Encoder | すべて Encoder 入力 | 入力文の内部関係を捉える |
| Masked Self-Attention | Decoder | すべて Decoder 入力 | 出力文の内部関係。**未来を見せない** |
| Cross-Attention | Decoder | Q は Decoder、K・V は Encoder | 入力文を参照して出力を作る |

**Masked** が重要です。Decoder は「次の単語」を予測するのが仕事なので、学習中に未来のトークンが見えてしまうとカンニングになります。そこで (n, n) のスコア行列の右上三角を `-∞` に置き換え、Softmax 後に重みが 0 になるようにします。

```
        t1    t2    t3    t4
 t1 [  ○    -∞    -∞    -∞  ]   t1 は自分だけ見る
 t2 [  ○     ○    -∞    -∞  ]
 t3 [  ○     ○     ○    -∞  ]
 t4 [  ○     ○     ○     ○  ]   t4 は全部見られる
```

### Feed Forward 層

各ブロックには Attention の後に **位置ごとの全結合層（Position-wise Feed Forward Network）** が入ります。中身は非常に単純です。

```python
# 各トークンに独立に適用される 2 層 MLP
def feed_forward(x):            # x: (n, 512)
    h = relu(x @ W1 + b1)       # (n, 2048)  いったん広げる
    return h @ W2 + b2          # (n, 512)   戻す
```

Attention が「トークン間で情報を混ぜる」層だとすれば、Feed Forward は「各トークンの中で情報を加工する」層です。この 2 つの役割分担が Transformer の骨格です。

### 残差接続とレイヤー正規化

各サブ層の出力は、必ず次の形で包まれます。

```
出力 = LayerNorm( x + SubLayer(x) )
```

- **残差接続（Residual Connection）**：入力 `x` をそのまま足す。第 5 章の ResNet と同じ考え方で、層を深く積んでも勾配が消えにくくなります。
- **レイヤー正規化（Layer Normalization）**：各トークンの特徴次元方向で平均 0・分散 1 に正規化。バッチ正規化と違ってバッチサイズに依存しないため、系列長が可変な自然言語処理に向いています。

この 2 つがあるおかげで、Transformer は 12 層・24 層・100 層以上と積み重ねられます。**「深く積める」ことが後のスケーリング則につながる**ため、地味ですが極めて重要な要素です。

### RNN と比べた並列化の優位性

Transformer が世界を変えた最大の理由は、精度そのものより**学習の速さ**です。

| 観点 | RNN / LSTM | Transformer |
|------|-----------|-------------|
| 系列の処理 | t-1 の計算完了後に t を計算（逐次） | 全トークンを同時に計算（並列） |
| GPU の活用 | 並列化しにくい | 行列積主体で GPU と相性抜群 |
| 離れた語への到達 | O(n) ステップ必要 | O(1) ステップで直接 |
| 計算量（系列長 n） | O(n) | O(n²) |
| 実際の学習時間 | 長い | 大幅に短い |

計算量のオーダーだけ見れば Transformer のほうが不利です。それでも勝てるのは、**GPU が「大きな行列積 1 回」を「小さな計算 n 回」より圧倒的に速くこなす**からです。ハードウェアの特性に合致したアーキテクチャが勝った、という見方ができます。

> **よくある誤解**：「Transformer は RNN の改良版」ではありません。再帰構造を完全に捨てた別物です。RNN が「記憶を持ち回る」のに対し、Transformer は「毎回すべてを見直す」設計です。

## 7.4 Transformer 以降の発展

### BERT（Encoder 系）と GPT（Decoder 系）

Transformer は Encoder と Decoder の両方を持ちますが、その後の発展は**片方だけを取り出す**方向に進みました。

![Transformer の発展](../ai-introduction/transformer-evolution.svg)

| | BERT 系（Encoder のみ） | GPT 系（Decoder のみ） |
|---|---|---|
| 見える範囲 | 前後両方（双方向） | 過去のみ（Masked） |
| 学習タスク | 穴埋め（Masked Language Model） | 次トークン予測 |
| 得意なこと | 分類・検索・固有表現抽出 | 文章生成・対話 |
| 出力 | 文や単語のベクトル表現 | 続きのテキスト |
| 使い方 | ファインチューニング前提 | プロンプトで直接指示 |

```
BERT の学習:  「今日の会議は [MASK] 時からです」 → 「15」を当てる
GPT の学習 :  「今日の会議は 15 時」            → 次は「から」を当てる
```

初期は「分類なら BERT、生成なら GPT」と棲み分けていましたが、モデルの大規模化に伴い Decoder 系が分類的なタスクもプロンプトでこなせるようになり、現在の LLM は Decoder 系が主流です。一方、検索やベクトル埋め込みの用途では今も Encoder 系が現役で、RAG の埋め込みモデルなどに使われています（第 8 章）。

### スケーリング則

Transformer が並列化で「大きく作れる」ようになった結果、経験的な法則が見つかりました。

> **スケーリング則（Scaling Laws）**：モデルのパラメータ数・学習データ量・計算量を増やすほど、損失は予測可能な滑らかさで下がり続ける。

![LLM の進化](../ai-introduction/llm-evolution.svg)

この法則の実務的なインパクトは 2 つあります。

1. **投資判断ができる**：「計算資源を 10 倍にすれば性能はこれくらい上がる」と事前に見積もれる。これが巨額の投資を正当化した。
2. **創発（Emergent Abilities）**：一定規模を超えると、明示的に教えていない能力（多段階の推論、コード生成など）が現れる現象が報告された。

ただし注意点もあります。パラメータだけ増やしてもデータが足りなければ非効率であり、「モデルサイズとデータ量はバランスよく増やすべき」という知見が後に示されました。近年は闇雲な巨大化より、データの質・学習の工夫・推論時の計算量に重点が移っています。

### 画像・音声への展開（ViT など）

Transformer は自然言語のために作られましたが、**系列であれば何でも扱える**汎用性がありました。

![Transformer のインパクト](../ai-introduction/transformer-impact.svg)

| 分野 | モデル | アイデア |
|------|--------|----------|
| 画像 | **ViT**（Vision Transformer） | 画像を 16×16 のパッチに分割し、各パッチを 1 トークンとして扱う |
| 音声 | Whisper など | 音声のスペクトログラムを系列として扱う |
| 動画 | 各種 Video Transformer | 時空間のパッチを系列化 |
| 生物 | AlphaFold 系 | アミノ酸配列を系列として扱う |
| マルチモーダル | 各種 VLM | テキストと画像のトークンを同じ系列に並べる |

ViT の発想は単純です。

```
224×224 の画像
   ↓ 16×16 のパッチに分割
14 × 14 = 196 個のパッチ
   ↓ 各パッチを平坦化して線形変換
(196, 768) のトークン列   ← あとは通常の Transformer Encoder と同じ
```

ただし ViT は CNN が持つ「近くのピクセルは関係が強い」という事前知識を持たないため、**大量のデータがないと CNN に負ける**という特徴があります。データが潤沢なら ViT、限られているなら CNN、というのが現在の実務的な目安です。

> **なぜ重要か**：異なるモダリティを同じアーキテクチャで扱えるということは、テキストと画像を同じモデルに同居させられるということです。これが第 8 章で扱うマルチモーダルモデルの土台になっています。

## まとめ

本章では、現代 AI の基盤である Attention と Transformer を学びました。

✅ **Attention は「微分可能な辞書引き」** — Query で探し、Key で類似度を測り、Value を加重平均する
✅ **Self-Attention は系列が自分自身を見る仕組み** — (n, n) の総当たり表を作り、離れた語にも 1 ステップで到達できる
✅ **Transformer は再帰を捨て、Attention + Feed Forward + 残差 + LayerNorm だけで構成される** — 並列化できることが最大の武器
✅ **Encoder 系（BERT）と Decoder 系（GPT）に分岐し、スケーリング則が巨大化を後押しした**
✅ **画像・音声など系列化できるものすべてに展開され、マルチモーダルの土台になった**

次章では、この Decoder 系 Transformer を極限まで大きくした LLM が実際にどう動き、どう実務のシステムに組み込むのかを見ていきます。
